# Урок 4.1 — Полный README + SPEC

> **Зачем:** Большой проект требует более детальной spec. Здесь учимся разбивать на фазы и чётко определять MVP.

---

## Структура для большого проекта

```markdown
# README: [название проекта]

## Что это
[2–3 предложения о сути]

## Зачем
[Проблема которую решает]

## Кто использует
[Роли и сценарии]

## Статус
[Фаза 1 в разработке]

---

# SPEC: MVP (Фаза 1)

**Цель фазы 1:** [минимально рабочая версия]
**Пользователь:** [конкретная роль]
**Входные данные:** [что на входе]
**Результат:** [что на выходе]
**Ограничения:** [рамки]

**Что НЕ входит в MVP:**
- [фича 1 — оставляем на потом]
- [фича 2 — оставляем на потом]
```

---

> [!NOTE] Правило фаз
> MVP не значит "плохо". MVP значит "только то что необходимо для первого запуска". Всё остальное — Фаза 2.

---

## Проверь себя

> [!QUESTION] Закрой страницу и ответь
> 1. В чём разница между README и SPEC?
> 2. Что такое "Что НЕ входит в MVP" и зачем это писать?
> 3. Как определить что что-то оставить на Фазу 2?

> [!SUCCESS] Действие
> Выбери вариант проекта (LMS или Dashboard). Напиши README + SPEC по шаблону выше.
