# Урок 4.2 — После первого промта: что видишь и что делать дальше

> **Зачем:** После первого промта Claude Code генерирует файлы. Большинство людей не знают что дальше — открыть? запустить? переписать? Этот урок объясняет весь путь.

---

## Что происходит после первого промта в Claude Code

```
Ты отправил дизайн-бриф + SPEC.md
         ↓
Claude Code создаёт файлы проекта
(app/, components/, styles/, package.json...)
         ↓
Ты запускаешь локально — видишь результат в браузере
         ↓
Оцениваешь: что хорошо, что не так
         ↓
Итерируешь — по одной правке за раз
```

---

## Как запустить и увидеть сайт локально

```bash
# В терминале, в папке проекта:
npm install        # один раз — устанавливает зависимости
npm run dev        # запускает локальный сервер

# Открой в браузере:
http://localhost:3000
```

Каждый раз когда Claude Code меняет файл — обновляй браузер, видишь результат.

---

## Как оценивать первый результат

Смотри на три вещи по порядку:

**1. Структура (layout)**
Правильно ли расположены блоки? Есть ли все секции из SPEC?
→ Если нет — скажи Claude что добавить/переместить

**2. Цвета и типографика**
Используются ли правильные HEX-коды? Правильный шрифт?
→ Если нет — укажи конкретно что не так и какой должен быть

**3. Контент**
Правильные ли тексты? Нет ли выдуманных данных?
→ Это галлюцинации — подробнее в следующем уроке

---

## Как давать правки — правило одной задачи

```
❌ Плохо:
"Измени цвет кнопок, добавь анимацию, переделай footer,
и сделай шрифт крупнее на мобильном."

✅ Хорошо:
"Измени цвет кнопок с серого на #6F23EE.
Только кнопки, ничего больше."
```

Одна правка за раз. После каждой — смотришь результат в браузере.

---

> [!WARNING] Spot the Mistake
> После первого промта разработчик видит что не нравится цвет заголовка. Он пишет: «Переделай дизайн полностью — этот мне не нравится».
>
> **Что не так?** «Переделай полностью» — это сброс прогресса. Claude заново придумает что-то случайное. Правильно: точно назвать что не так и что должно быть вместо этого.
