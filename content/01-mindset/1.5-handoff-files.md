# Урок 1.5 — Как передать задачу

> **Зачем:** Три файла делают проект понятным и для Claude, и для разработчика — без звонков и объяснений.

---

## Три файла

### README.md — что это и зачем
```markdown
# Название проекта

## Что делает
[2–3 предложения — суть проекта]

## Кто пользуется
[Роль и зачем]

## Статус
[В разработке / Готово / MVP]
```

### SPEC.md — что должно делать
```markdown
## Цель
## Пользователь
## Входные данные
## Результат
## Ограничения
## MVP (что входит в первую версию)
```

### CLAUDE.md — инструкция для Claude
```markdown
# Проект: [название]

## Контекст
[Кто мы, что продаём, зачем этот инструмент]

## Стек
- Next.js 14 (App Router)
- Tailwind CSS
- Vercel (деплой)

## Правила
- Не удаляй существующие компоненты без подтверждения
- Пиши TypeScript, не JavaScript
- Перед большими изменениями — опиши план

## Что НЕ делать
- Не меняй структуру БД без явного запроса
```

---

> [!NOTE] Почему CLAUDE.md — главный
> Claude Code читает этот файл **автоматически** при старте каждой сессии. Это значит: один раз написал правила — Claude всегда их помнит в этом проекте. Разработчик тоже читает этот файл и сразу понимает контекст.

---

> [!WARNING] Spot the Mistake
> Разработчик получает проект с одним файлом:
> ```
> app.js — 800 строк кода
> ```
> Без README, без SPEC, без CLAUDE.md.
>
> **Что не так?** Он потратит час только на то чтобы понять что делает проект. Claude при следующей сессии "забудет" контекст. Каждый раз нужно объяснять заново.
