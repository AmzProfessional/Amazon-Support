# Урок 3.1 — Пишем SPEC.md

> **Зачем:** Прежде чем что-то делать — описываем что хотим получить. Это занимает 5 минут и спасает от часов переделок.

---

## Заполняем шаблон для нашего проекта

```markdown
## Spec: Анализатор отзывов конкурента

**Цель:** получить структурированный список инсайтов из отзывов конкурента
**Пользователь:** менеджер по продукту, использует для брифа команде
**Входные данные:** 50–100 отзывов, вставляю вручную текстом
**Результат:** три секции — топ-жалобы, топ-плюсы, незакрытые потребности
**Ограничения:** каждая секция до 5 пунктов, только факты, без домыслов
**MVP:** один промт, один запуск, один документ на выходе
```

---

> [!NOTE] Правило MVP
> MVP (Minimum Viable Product) — минимальное что решает задачу. Не строй сразу с базой данных и интерфейсом. Сначала — промт который работает. Потом — всё остальное.
